# MYV 운영 관리자 구축 계획 (2026-11-06)

## 현황 확인
- 공개 홈페이지: GitHub Pages 기반 정적 HTML.
- contact.html: 문의 유형(프로슈머/입점제안/일반), 이름, 브랜드명, 이메일, 연락처, 제목, 내용 입력 후 FormSubmit(info@myv.co.kr)로 이메일 발송.
- prosumer.html 신청 CTA: contact.html?type=prosumer.
- news.html: 기존 뉴스 카드가 HTML에 포함되어 있음. 콘텐츠 원본 및 외부 연동 방식은 추가 확인 필요.
- admin.html: 현재 없음.

## 우선순위
1. **인증/권한**: 관리자 로그인은 서버 측 인증 및 권한 검사. GitHub Pages HTML/JS에 비밀번호나 API 비밀키 절대 포함하지 않음.
2. **문의 접수 API**: Cloudflare Workers 또는 동등한 서버리스 백엔드 + DB. 서버측 유효성 검사, 스팸 방지, 개인정보 보존/삭제 정책, 전송 암호화.
3. **접수 통합**: prosumer, partner, general 3개 유형. 접수번호, 날짜, 이름, 연락처, 기업명, 내용, 상태, 담당자, 내부 메모, 처리 이력.
4. **상태**: 신규 → 확인 → 검토중 → 답변완료/승인/반려 → 보관. 삭제는 관리자 권한과 감사 로그 필수.
5. **뉴스 CMS**: MYV/PARTNER/GLOBAL, 제목, 요약, 본문, 대표 이미지, 발행일, 공개 상태, SEO 메타, 외부 기사 출처 URL. 수정/게시/비공개. 기존 38개 뉴스 이관 전 데이터 원본 확인.
6. **통계**: 실제 DB 접수량 집계. 방문 통계는 별도 익명 이벤트 수집 또는 분석 도구 연동, 동의 및 정책 확인.
7. **관리자 UI**: /admin/ 별도 화면. 데스크톱 사이드바, 모바일 대응. 대시보드, 문의관리, 뉴스관리, 통계, 설정.
8. **운영 QA**: 프로슈머/입점/일반 각각 테스트 접수 → 저장 → 권한 확인 → 처리 → 뉴스 게시 → 공개 화면 반영 → 모바일 테스트.

## 주의
GitHub Pages만으로 개인정보 접수 내역을 비공개로 저장하거나 안전한 관리자 로그인을 구현할 수 없음. 공개 저장소의 JSON, localStorage, 하드코딩 암호로 구현하지 말 것. 백엔드 및 인증 연결 전 실제 접수 관리가 작동한다고 표시하지 말 것.

## 구분
- 1차: 현재 소스 조사 및 안전한 데이터 구조/운영 화면 설계
- 2차: 인증, DB, 문의 API, 기존 폼 연동
- 3차: 뉴스 CMS 및 공개 페이지 데이터 연동
- 4차: 방문자 분석 및 운영 QA
